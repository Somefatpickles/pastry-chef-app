## Persistence and sync

`pastry-chef.bake-activity.v1` stores an account-keyed local envelope containing completion events and timestamped favorite states. Each completion uses a deterministic ID from its recipe ID and exact timestamp. Repeated logs use distinct timestamps, while migration and cloud echoes converge on the same event. Removing a bake retains a deletion marker, and unfavoriting retains a false state, preventing older snapshots or delayed writes from restoring either.

Guest data moves atomically into the first profile used in this browser. Later guest bakes can rejoin that same profile; a different profile does not inherit them. Other account caches remain separate. The account record, claim marker and clearing of guest data share a single localStorage write. Failed local writes do not report successful saves. Existing personal recipe copies remain local to the browser, while their bake-history snapshots can sync with the profile.

Firestore normally stores separate records under `bakingProfiles/{uid}/completions` and `/favorites`. Per-record transactions preserve deletion markers and reject stale favorite changes. If an existing installation's rules allow only its profile document, permission-denied subcollection reads/writes fall back to per-ID maps in that already-authorized document. The fallback preserves existing checklist data and concurrent additions. It is subject to Firestore's document-size limit; the subcollection layout avoids that long-term limit. The owner-only `firestore.rules` and `firebase.json` configuration support the subcollection layout. Repository publication and Netlify deployment do not themselves publish Firebase rules; the existing profile-document fallback supports installations that retain their current rules.

Local cache writes happen before upload. Realtime streams merge records by ID, wait for all initial sources and report cache metadata. Cached snapshots do not claim a completed cloud sync. A failed stream keeps an error state until retry; generation/account guards discard stale callbacks after account changes. Analytics and Profile expose retry actions, and local records remain available while cloud writes are pending or fail.
